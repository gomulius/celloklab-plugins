# Standalone SDK release — 1.0.0

## Mandatory Polish UI and default-off clinic AI opt-in

Every new or maintained platform module/plugin must use **Polish for all user-facing UI**, including partner/admin screens: titles/navigation, labels/buttons/help/placeholders/tooltips, accessibility names, loading/status/errors/validation, confirmations/toasts/notifications and output framing. English developer prose is allowed; internal IDs/API fields/stable codes remain unchanged. Wire statuses map to Polish labels and `charged`/`replayed` display „tak”/„nie”. This release localizes the AI reference demo, not every unrelated existing platform screen.

Every plugin requesting literal `AI` is hidden on all clinic-facing surfaces until platform-global activation plus explicit opt-in by that clinic's local administrator, including non-AI content. Authorized management consoles remain available. No-AI plugins retain existing role/page/plugin rules in all eligible clinics without AI settings/license/activation dependencies. Manual migration **080** adds default-off `tenant_plugin_ai_activations` beside ledger migration 079. No automatic backfill: existing `tenant_ai_feature_settings` is not approval and local administrators must explicitly re-enable each AI-requesting plugin. Existing grants/licensing/settings/credits and pending/replay/CSRF/idempotency protections remain independent.

## Release boundary

Manifest contract version: **SDK 1.0** (`SDK_VERSION="1.0"`). Python distribution and browser UI-kit: **1.0.0**. These are different version domains; do not change a manifest to distribution version by assumption.

The release supplies an independently installable, standard-library-only `celloklab_plugin_sdk` Python package, PEP 517 build backend/wheel/sdist, offline validator, public catalogs, starter and generated public partner ZIP. Host legacy imports are compatibility shims to the same public classes. Partners do not need private host source, database credentials or repository access.

## Shipped features

- Public context, registrar, UI/page/fragment contracts, protocols, email descriptor, page/capability/hook/token snapshots and static validation without importing plugin code or host modules.
- A starter own page, modal and floating panel with shared declarations, safe DOM text, local file selection and a local email template descriptor. It does not send email/upload files/mutate records by running the sample.
- Host-integrated UI mount/targeting/priority/stable identity, native shared style tokens/classes, modal/floating close/dirty/focus guards, native-toast adapter and caller-controlled async loader.
- Implemented browser runtime bridges for patients, visits/reception scheduling, existing clinical records, photos/attachments, care plans, clinic profile/services/read-only staff, bell notifications, approved local-source email/Resend jobs and neutral-text plugin AI. Exact methods/fields/scopes/headers are in `PLUGIN_API_REFERENCE.md`.
- Public `ai.py` contracts and explicit-allowlisted `examples/example_ai/` own page plus global right-panel button **Uruchom AI**, two templates, shared static JS and README: literal `AI`, active local staff, one derived host feature per plugin, administrator-owned configuration and independent tenant AI licensing/activation/credits. Unconfigured console entries are virtual disabled rows until an active model/provider is selected and saved; discovery does not persist configuration/grant access. Plugin system prompts are optional administrator-owned supplements to plugin user instructions; null/blank supplements are omitted, not invented. Native AI and multimodal prompts remain required; hash-shaped IDs alone do not exempt features. AI grants no patient retrieval or inferred clinical authority.
- Existing Case reads remain preserved and **frozen**, not expanded. Employee mutations are **permanently excluded**; staff reads remain.
- Existing manual schema prerequisites 074–078 and shared-core media tombstone/cleanup remain. Plugin AI adds manual migration **079** for the safe execution ledger and **080** for default-off explicit clinic approval; no automatic runner, no repeated confirmed SQL and no native Case/staff changes.

## Explicit nonfeatures and limits

No sandbox/security certification, marketplace/upload installer, general event delivery bus, partner HTTP wrappers/private Request export, generic database/table export, generic clinic jobs/capability-development kit or external API-key runtime. The narrow `trichology.record.changed` registration described below is implemented; it is not general event delivery. The API runs within the authenticated browser host session, separately from the external public API. Capability grants, UI visibility, version approval, email-source approval and actor/resource authority are separate gates. New persistence/jobs/capabilities require reviewed core/SDK impact and host adapters/manual administrator SQL.

The offline validator checks bounded static policy; it does not execute registration/Jinja, prove JavaScript safety or certify dynamically generated declarations. Catalog names are not proof of live mounts. Native Resend remains unchanged; plugin-local source requires exact approval and no ENV template maps. Provider acceptance never proves delivery.

The offline preview has **no real API, authentication, authorization, upload or email**. Its toast is visibly marked preview-only, not production native-toast styling parity. Public UI CSS/JS and design tokens are copied; fonts are not redistributed because licensing has not been established, so local fallback rendering differs. Browser visual review remains necessary.

AI atomically reserves/debits credits before dispatch: success consumes the reservation, definite provider failure refunds, uncertainty/crashed in-progress retains it pending manual reconciliation without automatic provider replay. Results expose safe execution metadata and optional first-success text; raw prompt/generated text are not stored and every replay is metadata only. Changed payload with the same UUID key is 409; no blind retries/fresh-key bypass. Existing prompt redaction is not an anonymity/security guarantee. Administrator parameter defaults inherit provider-specific feature → generic feature → model → call fallback, including null; explicit zero is retained. Reasoning budgets use provider-specific mappings (OpenRouter, native Anthropic and Gemini), not a generic output-token limit; unsupported direct integrations reject supplied budgets. Polish provider/model/feature instructions are available through clickable **i** help on the providers page. See the API reference for exact reasoning mappings, 20000-character/64 KiB payload and host-session/CSRF rules.

## Build and distribution

### Clinical trichology addition

The wheel/sdist/public source allowlist now includes `clinical_ai.py`: `TrichologySnapshot`, `TrichologySummaryPrompt`, `TrichologySummaryRegistration` and exact event/capability constants. The ZIP includes `examples/trichology_ai_summary/` with **five files plus README**: manifest, public-SDK entrypoint, UI declarations, `templates/summary.html`, `static/staticsummary.js`, README. Its plugin ID is `trichology.ai-summary`, requiring `AI` + `patient.read_trichology_record` + `ai.trichology_summary` and exact `trichology.record.changed`. This host-controlled transactional source-change automation is not a generic bus/job API or arbitrary clinical-prompt POST.

The Polish non-form read-only card follows the style guide/hook catalog: semantic `.clk-plugin-ui` section with a descendant `clk-ui-card`, shared header/title/body, readable source freshness instead of revision hashes, and distinct queued/uncertain-pending messages. The section is initially collapsed via native details/summary; a separate labeled result card and Polish date/time from the existing `generated_at` distinguish output from help/status. Date formatting preserves host wall-clock values and explicit offsets; absent/invalid values are hidden, not fabricated. Toggle/polling never generate or auto-expand. It uses authenticated session/CSRF/tenant GET and bounded polling (30 requests, 2-second intervals). The summary DTO is `status`, `source_revision`, `current_revision`, `is_current`, `text`, `generated_at`, `job_id`; statuses: `queued`, `processing`, `pending`, `failed`, `stale`, `succeeded`, `cancelled`, `absent`. Current clinical profile/assignment and assigned-patient authority remain mandatory even if the card is visible. Source-only scalar minimization/redaction do not guarantee anonymity. Host revalidates before decryption, provider and publication; disable/revocation blocks work, source-version changes suppress stale publication without refunding valid paid responses. A 300-second lease and maximum 6 pre-dispatch attempts do not permit retry after a committed dispatch fence: uncertainty stays pending for manual reconciliation. Metadata uses compact UI Kit spacing (`clk-ui-gap-1`, compact cards), margin-free read-only blocks and a compact result heading; the short Polish “AI — wymaga” phrase stays together, while surrounding text wraps responsively. This does not change summary content, dates, polling or generation.

**Clinical encrypted snapshots/artifacts persist; neutral completion output does not.** Ledger/audit/logs remain metadata-only. Activation needs only missing manually reviewed migration 081 plus confirmed 079/080, exact grants/version, explicitly active model/provider/feature, clinic licensing/credits and independent local administrator consent. Pilot administrators manually disable native `patient_summary_generation`; code never does so. Native AI/forms and existing frozen Case reads remain unchanged. Retention/patient deletion is a host deployment gate, not a partner SQL responsibility. No production MariaDB/provider/browser acceptance is claimed.

Administrator/release engineering commands from the host repository root:

```sh
python -m pip wheel ./partner_sdk --no-deps --no-build-isolation --no-index -w /tmp/celloklab-wheels
python -m venv /tmp/celloklab-partner
/tmp/celloklab-partner/bin/python -m pip install --no-index --no-deps /tmp/celloklab-wheels/celloklab_plugin_sdk-1.0.0-py3-none-any.whl
/tmp/celloklab-partner/bin/celloklab-plugin-validate partner_sdk/starter
python -m unittest discover -s partner_sdk/tests -v
python partner_sdk/build_bundle.py --output /tmp/celloklab-partner.zip
```

The stdlib backend builds without downloaded build dependencies; sdist embeds the public module so it can be rebuilt without host source. Verify clean-venv import/validator with the host checkout removed from Python path. Rebuild ZIP **after final documentation changes**, because documentation is copied at build time.

The ZIP uses explicit allowlists for public SDK source/catalogs (including `ai.py` and `clinical_ai.py`), wheel, starter, neutral AI reference and clinical trichology reference manifest/entrypoint/declarations/templates/static JS/README, preview and public guides. The public guide set is development, API reference, this release note, style guide, page/hook catalogs and email/notification contracts. Release engineering must include newly finalized public guides in the builder's allowlist and verify the resulting archive before delivery. **`PLATFORM_ADMIN_PLUGIN_INSTALLATION_SKILL.md` and `PLUGIN_SYSTEM_MAINTENANCE.md` must remain excluded**, as must AGENTS, private host/configuration, migrations, environment files, logs, audit/patient data and third-party fonts. Marker scanning supplements manual source/archive inspection; it is not proof that every secret format was detected.

A partner uses the extracted bundle's included wheel and starter, not these host build commands. See `PLUGIN_DEVELOPMENT_SKILL.md` and `sdk/README.md` in the distribution.
