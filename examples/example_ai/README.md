# Neutral AI reference plugin

## Documentation and bundled-code boundary

This README describes the inspected existing public demo, whose manifest version remains **1.0.0**. The surrounding guides document current **Python SDK 1.1.0** contracts, but this docs-only branch bundles older **SDK 1.0.0** code/catalogs/wheel; manifest SDK stays **1.0**, UI Kit **1.0.0**. Installing/rebuilding the checkout does not upgrade it to 1.1.0. This neutral demo adds no typed interview or booking functionality. See the [repository index](../../README.md), [SDK README](../../sdk/README.md) and [current API reference](../../docs/PLUGIN_API_REFERENCE.md). GitHub documentation needs no ZIP; no new demo/code/artifact is published here.

All new or maintained platform/module/plugin user-facing UI must be Polish, including titles/navigation, labels, help, accessibility names, validation/errors, status/loading/toasts and output framing; English developer prose and unchanged wire IDs/fields/codes are allowed. This demo maps stable states to Polish and flags to „tak”/„nie”, never raw English states/exceptions. Its fixed/default prompt explicitly requests Polish output; this is not a guarantee that every arbitrary provider response is Polish or a claim that unrelated legacy UI was translated.

Like every plugin requesting literal `AI`, the entire demo is hidden on all clinic-facing surfaces until platform-global activation plus explicit local clinic-admin opt-in. Authorized management consoles remain available to administrators. No-AI plugins keep existing role/page/plugin rules in all eligible clinics without AI settings. Manual migration **080** adds default-off `tenant_plugin_ai_activations` alongside ledger 079; no automatic backfill. Existing `tenant_ai_feature_settings` is not approval: each clinic administrator must explicitly re-enable the plugin. Generation/replay still enforce current grants/licensing/credits, and CSRF/idempotency/pending safeguards are unchanged.

This trusted in-process example registers one authenticated host page (`completion`) and a staff-only fragment in the existing `global.panel.right` host panel using only the standalone SDK. It requests exactly `AI` and declares `ui.page` plus `global.panel.right`; it has no patient, Case or employee API access and defines no custom server route. The panel has stable fragment ID `ai-completion-panel`, placement `global_panel`, and the same seven local staff roles as the page. Platform-admin paths are excluded by the host.

The panel's **Uruchom AI** button immediately submits the fixed neutral prompt “Napisz po polsku krótkie, przyjazne powitanie na warsztaty ogrodnicze.” without a modal. Its hidden read-only prompt never becomes editable, including after preparing a new execution. Output appears in the panel. The original own-page demo remains editable. Both use `completion.js`, root-local selectors and no prompt IDs; duplicate asset loads initialize each root only once. Roots with the same plugin and tenant share transient execution state, loader/status/output and the paid-execution lock, including explicit replay of the exact original prompt/key from either root. Different plugin/tenant identities remain independent. Loading the script never sends a request.

The host must provide `POST /api/plugins/example.ai/ai/completion?tenant_slug=...`, with JSON body `{"user_prompt":"Napisz po polsku krótkie, przyjazne powitanie na warsztaty ogrodnicze."}`, the session CSRF header and a UUID `Idempotency-Key`. The expected success envelope is `{"plugin_id":"example.ai","result":{"execution_id":"...","status":"succeeded","credit_cost":1,"charged":true,"replayed":false,"text":"Witaj na warsztatach ogrodniczych!"}}`. The public adapter is `AIProtocol.generate(context, user_prompt, idempotency_key)`; model, feature, system prompt and cost are host-owned. `plugin_ai_feature_id()` maps the plugin to its one stable host feature. Its task is supplied in `user_prompt`; the administrator may add an optional system-prompt supplement. Null/blank supplements are omitted without inventing instructions and do not block clinic activation/UI visibility. Dedicated legacy native AI generation is removed in the current host; it is not a supported compatibility API. A hash-shaped feature ID alone does not authorize plugin dispatch.

Administrator defaults inherit provider-specific feature → generic feature → model → call fallback: missing/null values inherit, zero is explicit. The providers page's clickable **i** help is Polish and explains configuration and supported reasoning; exact OpenRouter/Anthropic/Gemini mappings and unsupported-budget rejection are documented in `PLUGIN_API_REFERENCE.md`. The demo cannot override these controls.

The page bounds prompts to 1000 characters, renders generated output using `textContent`, uses the native UI-kit loader and toast adapter, and stores neither prompts nor output in browser persistence. Pending/failed output is never displayed. An uncertain response locks the exact prompt/key in transient page memory; only the explicit replay button can reissue it. Pending or conflicting requests cannot be bypassed with a new key. A new execution becomes available only after a terminal succeeded/completed/failed result. No background polling, automatic retries or provider credentials are included.

Execution/idempotency/audit persistence must contain safe metadata only, not prompt/output. Successful replays may also lack recoverable text. This example cannot enforce host/provider retention or authorization; those remain host responsibilities. Use only neutral text, never patient or confidential information. A replay denied by current authorization does not settle an earlier uncertain execution. Reloading loses the transient key; use administrative execution metadata rather than a new paid request to resolve uncertainty.

The trusted development example stays at version `1.0.0`; this addition does not deliberately invalidate existing version approval or grant new capabilities. Production source review remains mandatory; unchanged version is not approval of arbitrary source changes.

From the public repository root, after installing the bundled older wheel, check static declarations with `celloklab-plugin-validate examples/example_ai` (or `python -m celloklab_plugin_sdk.validation examples/example_ai`). The old validator is not proof of complete 1.1.0 contract support, dynamic registration or host security. Historical host/partner behavioral tests are not included or rerun by this docs-only update; no authenticated browser/MariaDB/provider acceptance is claimed. Administrator handoff and current availability/licensing/consent gates are documented in the [installation guide](../../docs/PLATFORM_ADMIN_PLUGIN_INSTALLATION_SKILL.md) and [maintenance guide](../../docs/PLUGIN_SYSTEM_MAINTENANCE.md).
