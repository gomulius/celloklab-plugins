There is no marketplace/upload installer, external API-key runtime, automatic dependency resolver, general event delivery bus, generic job executor or arbitrary DB export. ## Authorization invariants

Never equate capability grant, page visibility or administration with data authority. Re-read active user/tenant/local roles, current plugin version/state/grants and relevant assignments. Deny before decryption. Client `dashboard_type` is not an authority switch.

- General patient basic data: local reception or clinical roles. Clinical actors require active doctor profile/clinic assignment and assigned-patient scope even with additional reception/admin roles. Pure tenant/platform administrator, finance/customer roles cannot use clinical data routes.
- Full visits are clinical and own-doctor scoped. Clinical records/media/care plans require assigned patient; user assignment IDs and doctor-profile IDs are different domains.
- Scheduling/options/reschedule/cancel require literal local reception role. Mixed clinical/reception users retain own-provider/assigned-patient restrictions. Minimal appointment DTOs do not expose clinical data; exact-start collision checks are not working-hours/duration availability. Unknown consultation combinations fail closed rather than inferred.
- Clinic profile and staff directory require active local tenant admin. Service reads and create/write/delete require local tenant admin. Directory doctor_verified denotes active profile/local assignment, not professional licensing.
- Messaging self permits current local staff; staff messaging/recipient listing requires local tenant admin and active same-clinic staff recipient. No arbitrary address or patient/customer targeting.
- Case reads use separate relationship SQL: active local clinical role, not super-admin, responsible specialist or nonrevoked invited/active internal-doctor participation. Own documentation adds author/participant permission; published opinions are published-only. Do not replace this with the generic patient matrix or add a doctor-profile requirement that the Case facade does not implement.

Resource-not-found/denied responses must not reveal other-tenant or unassigned existence. Denial/audit metadata must omit payloads, query strings, medical values, storage keys and raw exception text. Global flags cannot grant clinical scope.

## Transactions, revisions and storage

Use same-connection authorization/locks, bounded allowlisted validation, scoped UPDATE/readback and transaction-bound audit for mutations. Assert commit/rollback behavior, audit failure and reassignment/revocation races, not merely source strings. Direct facade routes and legacy methods must not be assumed to have every newer hardening guarantee.

Patient identity/contact and trichology/legacy full-visit If-Match remain optional: `check_revision(None, …)` permits the write. Encourage client revision use, but do not claim universal mandatory concurrency protection. New media metadata/delete, care child patch/delete, clinic profile/service patch/delete, reception reschedule/cancel require current resource-domain revision. Creates/schedule/append and messaging use UUID idempotency keys; uploads do not. A network/500 failure may be uncertain: read back before retries, preserve dirty forms. Do not reuse one revision across domains.

Patient/user identity uses the core PII encryption helper/domain; sanitize/decrypt once, retain lookup hashes and clinic-scoped uniqueness. Trichology clinic records preserve existing storage semantics; do not silently add encryption without coordinated native reader/writer migration. Trichology is not physician Case documentation. Metadata descriptions likewise retain core semantics independently of encrypted file bytes. Use synthetic real encrypt→DTO tests, not production data or mock-only claims.

Uploads authorize before multipart parsing, require host CSRF verification and same-origin conditions, bound stream/file/body size, validate actual content/images, demand clean scanner result and encrypted Hetzner writes. Confirmed upload must not be followed by a new required audit that makes a committed success look retryable. Precommit object allocations can be reconciled; uncertain commit preserves storage pending review. Read URLs remain session-authenticated and private/no-store; static plugin assets are not protected clinical storage.
