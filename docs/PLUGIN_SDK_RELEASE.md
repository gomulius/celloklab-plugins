## Explicit nonfeatures and limits

No sandbox/security certification, marketplace/upload installer, general event delivery bus, partner HTTP wrappers/private Request export, generic database/table export, generic clinic jobs/capability-development kit or external API-key runtime. The narrow `trichology.record.changed` registration described below is implemented; it is not general event delivery. The API runs within the authenticated browser host session, separately from the external public API. Capability grants, UI visibility, version approval, email-source approval and actor/resource authority are separate gates. New persistence/jobs/capabilities require reviewed core/SDK impact and host adapters/manual administrator SQL.

The offline validator checks bounded static policy; it does not execute registration/Jinja, prove JavaScript safety or certify dynamically generated declarations. Catalog names are not proof of live mounts. Native Resend remains unchanged; plugin-local source requires exact approval and no ENV template maps. Provider acceptance never proves delivery.

The offline preview has **no real API, authentication, authorization, upload or email**. Its toast is visibly marked preview-only, not production native-toast styling parity. Public UI CSS/JS and design tokens are copied; fonts are not redistributed because licensing has not been established, so local fallback rendering differs. Browser visual review remains necessary.

AI atomically reserves/debits credits before dispatch: success consumes the reservation, definite provider failure refunds, uncertainty/crashed in-progress retains it pending manual reconciliation without automatic provider replay. Results expose safe execution metadata and optional first-success text; raw prompt/generated text are not stored and every replay is metadata only. Changed payload with the same UUID key is 409; no blind retries/fresh-key bypass. Existing prompt redaction is not an anonymity/security guarantee. Administrator parameter defaults inherit provider-specific feature → generic feature → model → call fallback, including null; explicit zero is retained. Reasoning budgets use provider-specific mappings (OpenRouter, native Anthropic and Gemini), not a generic output-token limit; unsupported direct integrations reject supplied budgets. Polish provider/model/feature instructions are available through clickable **i** help on the providers page. See the API reference for exact reasoning mappings, 20000-character/64 KiB payload and host-session/CSRF rules.
